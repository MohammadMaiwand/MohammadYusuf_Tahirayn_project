# گزارش آزمون واقعی — Smart Auto Answer

این سند نتیجهٔ **آزمون‌های واقعی** پروژه را ثبت می‌کند. هیچ نتیجهٔ ساختگی در این سند
نوشته نشده است؛ هر مورد یا با اجرای واقعی تأیید شده یا صریحاً «آزمون‌نشده» علامت خورده است.

---

## ۱. لایه‌های آزمون

پروژه دو لایهٔ آزمون دارد:

| لایه | ابزار | چه چیزی را می‌سنجد | فرمان اجرا |
|---|---|---|---|
| آزمون موتور تشخیص | jsdom + Node | منطق تشخیص DOM، محافظ «رد»، کلیک دوباره، تماس فعال | `node tests/extension_detector.test.cjs` |
| آزمون انتها-به-انتها | مرورگر واقعی + CDP | تزریق افزونه در صفحهٔ واقعی، کلیک خودکار روی دکمهٔ «پاسخ» | `python tests/browser_e2e.py --scenario voice` |

### ۱.۱ آزمون موتور تشخیص (jsdom)

در این آزمون، ماژول‌های واقعی افزونه (`shared.js`، `call-detector.js`، `answer-engine.js`
و آداپتورها) داخل یک DOM شبیه‌سازی‌شده بارگذاری می‌شوند و هشت صحنهٔ تماس بررسی می‌گردد.

**نتیجهٔ آخرین اجرا: `19 از 19 بررسی موفق`**

نمونهٔ خروجی:

```
PASS  ۱) واتساپ انگلیسی: دکمهٔ درست (Accept) انتخاب می‌شود  [top=Accept call-accept]
PASS  ۲) فارسی: دکمهٔ «پاسخ» انتخاب می‌شود (نه «رد»)  [top=پاسخ پاسخ]
PASS  ۳) برچسب منفی: «No answer / Missed call» انتخاب نمی‌شود  [top=Answer Answer]
PASS  ۴) فقط دکمهٔ رد: هیچ تماسی تشخیص داده نمی‌شود  [found=false acceptCount=0]
PASS  ۵) پاسخ خودکار: دقیقاً یک‌بار روی دکمهٔ پاسخ کلیک شد  [acceptClicks=1]
PASS  ۵) پاسخ خودکار: کلیک دوباره روی تماس فعال انجام نمی‌شود  [reason=duplicate]
PASS  ۶) محافظ رد: کلیک روی دکمهٔ رد مسدود می‌شود  [reason=decline_guard]
PASS  ۷) تماس فعال: به‌عنوان «قبلاً پاسخ‌داده‌شده» علامت می‌خورد  [alreadyActive=true]
PASS  ۸) سایت عمومی: تماس ورودی تشخیص داده می‌شود  [found=true]
```

### ۱.۲ آزمون انتها-به‌انتها (مرورگر واقعی)

این آزمون صفحهٔ شبیه‌ساز (`extension/test/mock-call.html`) را روی یک سرور محلی سرو می‌کند،
مرورگر را با افزونهٔ بارگذاری‌شده باز می‌کند، تماس را شبیه‌سازی می‌کند و منتظر می‌ماند تا
افزونه خودش دکمهٔ «پاسخ» را بزند.

**نتیجهٔ آخرین اجرا (روی Microsoft Edge): هر ۵ سناریو PASS**

```
--- voice ---   PASS — افزونه به‌صورت خودکار روی دکمهٔ «پاسخ» کلیک کرد (نه روی «رد»).
--- video ---   PASS — افزونه به‌صورت خودکار روی دکمهٔ «پاسخ» کلیک کرد (نه روی «رد»).
--- persian --- PASS — افزونه به‌صورت خودکار روی دکمهٔ «پاسخ» کلیک کرد (نه روی «رد»).
--- negative --- PASS — افزونه به‌صورت خودکار روی دکمهٔ «پاسخ» کلیک کرد (نه روی «رد»).
--- active ---  PASS — تماس از قبل فعال بود و افزونه هیچ کلیکی انجام نداد.
```

> **نکتهٔ مهم دربارهٔ Chrome:** در نسخهٔ پایدار Google Chrome (نسخهٔ ۱۳۷ به بعد)، بارگذاری
> خودکار افزونه با پرچم خط فرمان **مسدود** شده است. بنابراین آزمون خودکار از Microsoft Edge
> استفاده می‌کند (یا افزونه در Chrome به‌صورت دستی با «Load unpacked» بارگذاری می‌شود).

## ۲. آزمون‌های خواسته‌شدهٔ پرامت اصلی (TEST A تا TEST J)

در پرامت اصلی ده سناریوی آزمون واقعی خواسته شده بود. وضعیت واقعی هرکدام:

| آزمون | سناریو | روش بررسی | نتیجه | توضیح |
|---|---|---|---|---|
| TEST A | تماس صوتی ورودی واتساپ وب | صفحهٔ شبیه‌ساز (سناریو `voice`) | **PASS** | کلیک خودکار روی «پاسخ» تأیید شد |
| TEST B | تماس تصویری ورودی واتساپ وب | صفحهٔ شبیه‌ساز (سناریو `video`) | **PASS** | کلیک خودکار روی «پاسخ» تأیید شد |
| TEST C | تب پس‌زمینه | — | **NOT TESTED** | نیازمند تماس واقعی با حساب دوم |
| TEST D | کار در Word هنگام تماس | — | **NOT TESTED** | نیازمند تماس واقعی |
| TEST E | کار در Excel هنگام تماس | — | **NOT TESTED** | نیازمند تماس واقعی |
| TEST F | چند تب هم‌زمان | — | **NOT TESTED** | نیازمند تماس واقعی |
| TEST G | تماس از قبل فعال + چرخهٔ تشخیص | صفحهٔ شبیه‌ساز (سناریو `active`) | **PASS** | افزونه هیچ کلیکی انجام نداد |
| TEST H | فشردن F9 هنگام پایش | آزمون دستی دسکتاپ | **NOT TESTED** | میان‌بر سراسری؛ نیازمند آزمون دستی روی ویندوز |
| TEST I | قطع مرورگر / تعلیق تب | — | **NOT TESTED** | افزونه وضعیت تب را گزارش می‌کند، ولی سناریوی خودکار ندارد |
| TEST J | نبودن/غیرفعال‌بودن دکمهٔ پاسخ | آزمون موتور (صحنهٔ ۴ و ۶) | **PASS** | فقط دکمهٔ «رد» ⇒ هیچ کلیکی انجام نشد |

> چرا TEST A/B با صفحهٔ شبیه‌ساز انجام شده و نه تماس واقعی؟ چون انجام تماس واقعی واتساپ
> نیازمند **دو حساب** و **گوشی دوم** است که در محیط توسعه موجود نبود. صفحهٔ شبیه‌ساز دقیقاً
> **همان مسیر تشخیص** (DOM + آداپتور + موتور پاسخ) را اجرا می‌کند؛ فقط منبع تماس، شبیه‌سازی
> است. برای تبدیل این‌ها به PASS واقعی، کافی است روی رایانهٔ خودتان یک تماس واقعی بگیرید.

## ۳. نحوهٔ اجرای آزمون‌ها روی سیستم خودتان

### آزمون موتور تشخیص

```powershell
cd tests
npm install        # فقط بار اول
node extension_detector.test.cjs
```

### آزمون انتها-به-انتها با مرورگر واقعی

پیش‌نیاز: نصب بستهٔ `websockets`:

```powershell
python -m pip install websockets
```

سپس:

```powershell
python tests/browser_e2e.py --browser auto --scenario voice
python tests/browser_e2e.py --scenario video
python tests/browser_e2e.py --scenario persian
python tests/browser_e2e.py --scenario negative
python tests/browser_e2e.py --scenario active
```

`--browser auto` نخست Edge و سپس Chrome را امتحان می‌کند.

### آزمون دستی روی مرورگر خودتان

۱. افزونه را با «Load unpacked» بارگذاری کنید.
۲. فایل `extension/test/mock-call.html` را در مرورگر باز کنید.
۳. یکی از دکمه‌های «شبیه‌سازی…» را بزنید.
۴. اگر پاسخ خودکار روشن باشد، افزونه باید خودش دکمهٔ سبز «پاسخ» را بزند و در گزارش صفحه
   یک ردیف آبی («افزونه») ثبت شود.

---

## ۴. کرانه‌ها و محدودیت‌های صریح

- پاسخ‌دادن زمانی ممکن است که **رایانه روشن** و **مرورگر باز** باشد.
- اگر مرورگر تب را «معلق/خواب‌رفته» کند، تشخیص ممکن است تأخیر داشته باشد.
- اگر سایت نیازمند «تعامل واقعی کاربر» (Trusted User Activation) باشد، افزونه موفقیت را
  **ادعا نمی‌کند** و در گزارش‌ها «تأیید نشد» ثبت می‌شود.
- محتوای داخل `iframe`های محدودشده (cross-origin) قابل خواندن نیست و در گزارش‌ها صریحاً
  به‌عنوان محدودیت اعلام می‌شود.
